DNS 只显示 SERVFAIL？用 dig 查有没有扩展错误 EDE

星航2026-11-27— 次阅读
网络技术

排查机场线路时，域名查询出现 SERVFAIL，只说明这次 DNS 响应报告了失败，不能单独说明失败卡在哪里。部分解析器还会通过 EDNS 附上一条 EDE（扩展 DNS 错误），例如提示 DNSSEC 验证没有通过，或没有联系上权威服务器。先读 DNS 头里的 RCODE，再把 EDE 当作补充线索。

示意图。DNS 响应码是主结果，EDE 是同一个响应里可能附带的诊断说明。

留下原始查询条件，再找附注

在装有 ISC BIND dig 的环境中，可以先查一个公开域名来熟悉输出。下面不指定服务器，记录的是 dig 当次实际使用的解析器，不保证和浏览器或机场客户端使用同一个。

dig -r example.com. A +edns=0 +comments

-r 不读个人 .digrc；+edns=0 显式带 EDNS 查询；不要使用只输出短答案的方式。正式排查时换成已授权查询的公开域名和实际类型，私有域名只在其批准的解析器上检查。首先记 status、SERVER、时间与查询类型，再在 OPT PSEUDOSECTION 查有没有 EDE 和其编号。上面的命令不假定一定有 EDE；客户端若用单独的加密 DNS，也要参考它自己的诊断，不能用系统查询代替。

一手规范中的附注示例 下一步
6：DNSSEC Bogus 这个解析器报告验证进入 Bogus 状态；若是自己管理的域名，从签名和委派记录核对，不关闭验证换取一个结果。
22：No Reachable Authority 解析器报告没有可达的权威服务（或权威未予答复）；记录查询时间和解析器，请维护者检查权威端可达性。
有 RCODE，没 EDE 写“未提供原因”。解析器可不提供，中间转发也可不保留，不能靠缺失倒推原因。

用两行证据交接

第一行写“时间｜解析器｜域名与类型｜RCODE”，第二行写“EDE 编号与必要的脱敏备注”，再说明同一条件能否复现。标准允许有些 NOERROR 回复也带附注；它不会改写 DNS 状态，也不能单靠这条文字验证故障原因。看到一条原因提示，不等于已经定位到机场节点或订阅服务，先用这两行让维护者能复查同一问题。
