机场测速要不要固定 IP？用 curl --resolve 做一组 DNS 对照

王牌飞行员2026-09-29— 次阅读
网络技术

机场测速要不要固定 IP？用 curl --resolve 做一组 DNS 对照

同一个测试域名连续测速，结果忽快忽慢，不一定说明机场节点正在波动。域名可能通过 DNS 返回多个入口，不同入口的距离、负载和线路都可能不同。如果每次请求实际连到不同 IP，测速表里就混入了“节点差异”和“目标入口差异”两种变量。

这时可以用 curl --resolve 做一组固定入口对照。它不会修改系统 hosts 文件，只在当前 curl 请求中把指定域名、端口映射到指定 IP，适合短时验证。

先记录正常解析结果

先在不固定 IP 的情况下请求一个公开、允许测试的小页面：

curl -o /dev/null -sS \
  -w "remote_ip=%{remote_ip} connect=%{time_connect} total=%{time_total}\n" \
  https://example.com/

连续执行三至五次，记录 remote_ip、连接时间和总时间。如果 remote_ip 经常变化，说明这一批数据并非严格的同一目标入口对照。

再用 --resolve 固定域名与 IP

从刚才的记录中选择一个已经实际返回的 IP，再执行：

curl --resolve example.com:443:目标IP \
  -o /dev/null -sS \
  -w "remote_ip=%{remote_ip} connect=%{time_connect} total=%{time_total}\n" \
  https://example.com/

这里仍然使用原域名访问，因此 HTTP Host 和 TLS 证书校验保持正常；改变的只是本次连接使用的目标 IP。不要把 URL 直接改成 https://目标IP/，否则可能遇到证书名称与虚拟主机不匹配，得到另一类错误。

做两组而不是只看一次

建议在同一网络、同一机场节点下完成两组：

  1. 正常 DNS 解析，重复三至五次；
  2. 固定一个已解析到的 IP，重复三至五次。

每次记录成功或失败、remote_ip、time_connect 和 time_total。如果固定 IP 后结果明显收敛，原来的波动更可能来自目标入口变化；如果两组都波动，再检查机场节点、Wi-Fi、丢包和本地负载。

哪些结论不能下

固定 IP 只是排除一个变量，不能证明某家机场长期稳定，也不能代表所有网站、所有时段或所有地区。CDN 入口可能变化，旧 IP 也可能失效，因此不要把固定映射长期写进系统配置。

做机场推荐或试用比较时，先说明是否固定目标入口，再给出失败次数和时间分布，比只展示一次最快结果更容易复查。

验收清单

  • 正常组和固定 IP 组使用同一 URL、同一节点和相近时间窗口；
  • 固定 IP 来自该域名当前实际解析结果；
  • remote_ip 与预期一致；
  • HTTPS 证书校验保持开启；
  • 结论只描述本次条件下的差异。
