DNS 新增 CNAME 被拒绝？先查同名 A、AAAA 与已有别名

星航2026-11-10— 次阅读
网络技术

给站点或机场相关帮助页新增 CNAME 时，后台提示“同名记录冲突”。先看完整主机名，而非只看记录值。Cloudflare 官方 DNS 文档明确说明：同一名称已存在 A、AAAA 或 CNAME 时，创建冲突的 CNAME/A/AAAA 组合会被拒绝；同名多个 A/AAAA 则是另一回事。

先做只读清单

记录你想修改的完整主机名、类型、目标值和当前权威 DNS 服务商。到该主机名的记录列表，查已有 A、AAAA、CNAME；注意 www 与根域、下级子域不是同一个名称。保存现有记录与业务用途，尤其是正在提供网站、邮件验证或第三方服务的记录。

示意图：同一名称若已有地址记录，新增别名时要先决定最终配置。

三种常见判断

  • 已有 A/AAAA，准备改为 CNAME：先确认新服务要求的目标与旧地址用途，安排变更窗口，不要直接删除正在用的地址记录。
  • 已有 CNAME，准备加 A/AAAA：通常要选择保留别名或改成地址记录；复制一条同名记录并不能让两者都按预期生效。
  • 看似没有同名记录：核对是否在错误的 DNS 区域编辑，或服务商对根域做了别名扁平化；以当前权威配置为准。

不要把 CNAME 冲突归咎于机场节点或浏览器 DNS 缓存。先在管理界面解决配置关系，再用权威查询和公开解析结果核对生效；解析延迟还要考虑缓存和旧 TTL。验收是能画出该主机名最终只按预期方式指向目标，且原网站功能仍可访问。本文只是 DNS 检查方法，不要求读者改本站现有配置。
