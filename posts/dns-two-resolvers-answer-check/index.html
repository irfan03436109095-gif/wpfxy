两个 DNS 服务器返回不同地址？指定解析器记录查询结果

老王2026-10-15— 次阅读
网络技术

同一个机场官网域名，在两台设备或两个 DNS 解析器上查到不同地址，不足以单独证明“节点被劫持”或“域名已经完全生效”。Microsoft 的 Resolve-DnsName 可以指定 DNS 服务器和记录类型；Cloudflare 的 DNS 故障文档也指出，上游解析器的缓存时间不同，会让答案在一段时间内不一致。

固定查询条件

先记录完整域名、查询时间、所用网络、A 还是 AAAA 记录。不要把 www 与根域名混为一谈，也不要把 IPv4 与 IPv6 地址直接比较。示例命令用自己有权限查询的域名和解析器地址替换占位符：

Resolve-DnsName -Name example.com -Type A -Server 解析器一的地址 -DnsOnly
Resolve-DnsName -Name example.com -Type A -Server 解析器二的地址 -DnsOnly

-Server 指定查询目标；不填时会使用接口配置的 DNS 服务器。记录响应地址、是否报错与观察时间，避免只截取其中一行。

示意图：固定域名和记录类型后分别查询两个解析器，再记录返回地址与时间。

如何读差异

两边都有地址但不同，先看站点是否使用多地址、CDN 或不同地区的解析策略，再复测公开 HTTPS 页面；只有一边返回 NXDOMAIN，可能与负缓存或尚未同步的记录有关。Cloudflare 提醒，清本机 DNS 缓存不会清掉上游递归解析器的缓存。

不要直接把任意解析器返回的 IP 写进 hosts 文件，也不要只因 DNS 返回一致就认定官网安全。另用浏览器正常 HTTPS 校验证书和页面内容；如站点正迁移，保留时间序列比一次结果更有解释力。

验收

同一网络、同一域名和记录类型下重复查询，记录差异何时消失，并单独核对 HTTPS 是否真正可访问。机场推荐里关于“域名已生效”的说法，应能对应可复查的 DNS 与网页结果。
