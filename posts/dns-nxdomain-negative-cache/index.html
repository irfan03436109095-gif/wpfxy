刚新增 DNS 记录却仍报 NXDOMAIN？别只看新记录的 TTL

星航2026-11-09— 次阅读
网络技术

你刚给域名新增记录，权威服务器已经能回答，但某台设备仍收到 NXDOMAIN，不能立刻断定机场 DNS 把记录“吞了”。DNS 不存在的回答也可能被递归解析器缓存；新记录的普通 TTL 与旧错误回答剩余的缓存时间不是一回事。

先确认查询对象完全一致

把完整域名、记录类型（A、AAAA 等）、使用的解析器和查询时间写下来。少一个子域、查错记录类型或把浏览器缓存与系统解析结果混在一起，都会让对照失真。不要用含订阅令牌的专属域名截图公开排障。

示意图：新记录生效与旧的 NXDOMAIN 缓存到期是两个不同时间点。

分别看权威与递归回答

先查询负责该域的权威服务器，看它现在是否已返回预期记录；再向你设备实际使用的递归解析器查询同一名称和类型，记下返回码与 SOA 信息。若权威已更新、递归仍给 NXDOMAIN，才有负缓存这一可能。若权威仍答不存在，应先检查记录是否保存到正确的区域和名称。

RFC 2308 说明，带 SOA 的 NXDOMAIN/NODATA 回答可被缓存，负回答的 TTL 与 SOA 字段有关；RFC 9520 又明确了部分解析失败的缓存要求。这里不提供一个适用于所有解析器的固定等待分钟数，因为解析器自身限制和实际链路也会影响结果。

怎样验收恢复

记录权威侧首次出现新记录的时间，隔一段时间对同一个递归解析器重查同一域名和类型。若返回由 NXDOMAIN 变为目标记录，再用原应用做实际访问；若一直失败，检查浏览器安全 DNS、系统缓存和代理客户端 DNS 路径。单纯清理电脑缓存无法清除远端递归解析器的缓存。

这套方法帮助你定位 DNS 层，不证明节点速度、套餐质量或服务商故障。
